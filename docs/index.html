FIELD NOTES / 001NAV2 LIFECYCLE LAB · ROS 2 JAZZY
Operating a robot's navigation software

A destination is simple.
Being ready to move isn't.

You ask a robot to go somewhere. Several Linux processes must agree on the map, the route, and the motion. This lab teaches us to tell whether those parts are actually ready—and to collect evidence when they aren't.

01 / Follow the request

Animation explains the architecture; it is not a live connection to ROS.

02 / Try the lifecycle

Alive ≠ ready.

A process is a running program. A lifecycle state tells us whether its navigation behavior is enabled.

PROCESS: ALIVEACTIVE

Active: the controller is enabled to compute velocity commands when a task requests them.

This switch is an educational model. Our actual experiment called Nav2's lifecycle service and queried the controller state. It paused after both goals finished.

03 / Replay the recorded movement

One room. Two destinations.

Actual action feedback, sampled for display. Sample index is not elapsed time. The room is intentionally empty. Success allows a 0.25 m position tolerance.

05 / Why this is useful

Learn to diagnose a real system before adding to it.

When navigation fails, “the program is running” is an incomplete answer. We need to check lifecycle readiness, requests, responses, logs, and shutdown. This baseline gives us a working reference to compare against a deliberately broken run.
